# Research — 007

- **Decision**: React 18 + Vite + TypeScript, react-router v6, sem biblioteca de componentes visuais (CSS próprio com variáveis e `prefers-color-scheme`). **Rationale**: constitution fixa React/Vite/TS; superfície pequena, poucas dependências, build rápido. **Alt.**: MUI/Ant Design (mais peso e curva para 3 telas).
- **Decision**: Estado de servidor com um hook simples `useApi` (fetch + estados loading/error/data + `reload`) em vez de React Query. **Rationale**: nenhuma necessidade de cache compartilhado; menos dependências; testável com fetch mockado.
- **Decision**: Cliente HTTP único (`api/client.ts`) com caminhos relativos `/v1`, cabeçalho `X-Operator-Id` lido do `localStorage`, parse de `application/problem+json` em `ApiError` (status, title, detail, errors). Em desenvolvimento o Vite faz proxy `/v1` → `http://localhost:8080`; no compose o nginx faz proxy `/v1` → `api:8080` (mesma origem, sem CORS).
- **Decision**: `ActorContext` com escopo de requisição preenchido por `ActorMiddleware` (`X-Operator-Id` válido pelo padrão `^[A-Za-z0-9._@:-]{1,100}$`; inválido → 400 problem+json). Handlers disparados pela API (cancelar, reprocessar processo e proofing, reconciliar, link de download, criar processo) usam `actor.Type/actor.Id`; workers e eventos de sistema mantêm `SYSTEM`. Sem cabeçalho: `CONSUMER`/`api` (compatível com as specs anteriores). Substituído pelo sujeito do token na spec 008.
- **Decision**: Lista: `GET /v1/signature-processes` com filtros `status`, `operationalStatus`, `q` (ILIKE em id e external_id) e paginação; provider por subconsulta em `provider_process`; contagem de assinantes por subconsulta; `document_file_name` em coluna própria (migration com `UPDATE ... SET document_file_name = request_json->'document'->>'fileName'`). SLA calculado em memória sobre a página (regra FR-002; limite `Sla:SigningMinutes`, padrão 60).
- **Decision**: `GET /v1/signature-processes/{id}/provider` devolve metadados do provider e grava `PROVIDER_METADATA_INSPECTED` (leitura auditada, consistente com PRD seção 36). 404 quando o processo ainda não tem registro no provider.
- **Decision**: Download no portal: `POST .../download-link` com `artifactId` e `window.location.assign(url)`. No compose `Artifacts__PublicBaseUrl` passa a `http://localhost:3000` para que o link passe pelo proxy do nginx (`/v1/downloads/...`).
- **Decision**: Timeline = journal mapeado por uma tabela de rótulos legíveis (`PROCESS_CREATED` → "Process created", etc.), com fallback para o tipo cru; Audit Trail mostra o mesmo journal em tabela com ator, correlationId e causationId; paginação "Load more" (50 por vez).
- **Decision**: Abas por query string `?tab=` (compartilhável); Errors = operações `FAILED/DLQ/RETRY_PENDING` + dead letters do processo (`/v1/dead-letters?processId=`, pendentes e resolvidas) + eventos de falha.
- **Decision**: Testes do portal: Vitest + jsdom + Testing Library; `fetch` substituído por um roteador de fixtures (`mockApi`) que também registra chamadas, para afirmar cabeçalhos (`X-Operator-Id`) e bodies. Verificação visual no navegador como checagem manual complementar (não substitui os testes).
- **Decision**: Imagem do portal em duas etapas (node:20 build → nginx:alpine) com `try_files` para SPA e `location /v1/ { proxy_pass http://api:8080; }`.
